# CareBridge – GCP 3-tier architecture

```
                         Internet
                            |  tcp/80 (allowed_web_cidrs)
                   +--------v---------+     subnet 10.10.1.0/24
  TIER 1  WEB      |  carebridge-web  |     public IP (static)
                   |  nginx + React   |     SA: no permissions
                   +--------+---------+
                            |  tcp/4000  (only from tag "web")
                   +--------v---------+     subnet 10.10.2.0/24
  TIER 2  APP      |  carebridge-app  |     no public IP
                   |  Node/Express API|     SA: reads app secrets, creates upload backups
                   +--------+---------+
                            |  tcp/3306  (only from tag "app")
                   +--------v---------+     subnet 10.10.3.0/24
  TIER 3  DATA     |  carebridge-db   |     no public IP
                   |  MySQL 8         |     SA: reads 2 DB secrets,
                   +--------+---------+         creates DB backup objects
                            | nightly dump
                   +--------v---------+
                   | private GCS bucket|    DB + uploads backups, 14-day lifecycle
                   +------------------+
                         ^             ^
                    DB backup       app uploads backup
```

| Control | How |
|---|---|
| Network isolation | custom VPC, one subnet per tier; firewall allows only Internet->web, web->app, app->db |
| No public admin ports | SSH only through Identity-Aware Proxy (`--tunnel-through-iap`), OS Login, no project SSH keys |
| Outbound for private tiers | Cloud NAT (outbound only, no inbound) |
| Secrets | random passwords generated by Terraform, stored in Secret Manager, read at boot with the VM's own service account; nothing in the repo or in VM metadata |
| Least privilege | one service account per tier, secret-level IAM bindings, backup writer cannot read or delete |
| Host hardening | Shielded VM (secure boot, vTPM, integrity monitoring), Debian 12 |
| Recovery | scheduled DB dumps and doctor-upload archives to GCS; local Compose restore drill is defined in CI |
| Versioned deploys | VMs run `ghcr.io/<owner>/carebridge-{frontend,backend}:<image_tag>`; change `image_tag`, `terraform apply` to roll forward or back |

## Cost (be honest with yourself)
- Some resources may qualify for limited Always Free usage in supported US regions, but eligibility and quotas vary by account and resource. Do not assume the full stack is free.
- **Not fully free:** the app VM, database VM, Cloud NAT and related network resources can incur charges. Exact cost depends on region, usage and current pricing; use the GCP Pricing Calculator before applying.


## Important deployment boundary

The current public web tier serves HTTP on port 80 directly from a VM IP. This is acceptable only for a controlled portfolio demo with synthetic data. A production service needs HTTPS with a domain/load balancer, a managed database, high availability, centralized monitoring and a verified restore process.
